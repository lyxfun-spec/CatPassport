# 上下文管理实现说明

Windows 后端将消息、Run、工具调用、审批和成果记录作为 SQLite 权威数据保存。发送给模型的上下文只是派生视图：当前有效摘要、有界近期原始事件、当轮输入、系统提示、工具 Schema、已加载的 Skill/工具结果和输出预留。

每次 Chat 请求和 Work 模型轮次前，后台都会序列化供应商实际请求结构，并按模型能力配置预算。默认预留 4,096 个输出 Token 和 5% 安全余量；输入预算使用率达到 70% 时安排压缩，80% 时优先压缩。供应商返回 Usage 时会持久化实际用量，否则诊断会明确记录为保守 UTF-8 估算。

压缩是使用当前会话模型和 API 设置发起的独立低温请求，只在安全边界执行。Work 不会拆开尚未完整配对的助手工具调用和工具结果。摘要记录覆盖范围、来源摘要和版本；满足最小压缩收益后才在事务中切换为有效版本。压缩失败不会覆盖旧摘要或原始历史。压缩输入过大时会分批滚动处理。

历史检索采用 SQLite FTS5 与完全本地、零额外依赖的 Unicode 词/字符 n-gram 向量，再用 RRF 融合排序。向量是按稳定消息 ID 和内容指纹生成的派生数据；FTS5 或向量索引失败时仍可回退到有界关键词查询。本地向量能改善模糊表达和中英文混合召回，但不是神经网络 Embedding；`ILocalEmbeddingProvider` 接口允许以后在不改变存储和排序语义的情况下换成随应用打包的 ONNX 模型。

Chat 只暴露 `search_conversation_history`，并严格限定当前对话；同一入口支持有界搜索和按稳定消息 ID 读取原文。Work 不增加模型工具，而是在既有会话工作区生成 `work/.context/history.jsonl`、`status.json` 和 `search_history.py`。该副本单向导出，会清理形似凭证的工具字段，并记录水位线和完整性哈希；删除或修改副本不会影响权威历史。

大型 Work 工具结果会继续完整保存在权威工具记录中，并完整落盘到 `work/.context/tool-results/`。模型只接收短预览和工作区相对路径。审批状态、活动 Run、待处理用户消息和工具终态始终由业务状态维护，不依赖模型摘要。

已知限制：

- 模型窗口是内部能力配置，供应商发布能力变化后需要同步更新。
- 无供应商 Usage 时使用有意偏保守的估算；只有拿到实际 Usage 后才能校准。
- 无法拆分的单条当前输入仍可能超过最小安全请求；此时后台保存进度并明确报错，不会静默截断。
- Work 历史副本在模型轮次和任务完成边界刷新，不会在某个工具仍运行时持续改写。
